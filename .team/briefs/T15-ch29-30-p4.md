## Yêu cầu
- **Ch29:** pipeline Producer → Kafka → consumer Scala → parse → validate schema → dedup (store bền: ví dụ file/SQLite/PostgreSQL nhúng zonky như Ch15 —
  chọn và giải thích) → event-time → error routing (DLT kèm lý do) → retry → sink → monitoring (lag, counters) → recovery. So sánh consumer tự viết với Spark
  Structured Streaming/Flink **ở mức khái niệm + bảng semantics**; nếu chạy thử Structured Streaming thì phải là build Scala 2.13 riêng; không mặc định cùng semantics.
- **Ch30:** at-most/at-least/exactly-once với **điều kiện chính xác** (phạm vi thành phần/giao dịch), offset management, replay, recovery sau crash (giết consumer giữa
  chừng bằng thí nghiệm thật trên broker nhúng), ordering theo partition/key, poison message, backpressure, monitoring vận hành. Nếu dùng Kafka transaction
  (transactional producer + read_committed) thì chạy thật và nói rõ phạm vi; không dùng "exactly-once" như cam kết tuyệt đối.
- **P4:** producer, topic, consumer, schema validation, transformation, error handling, retry, DLT, monitoring; test end-to-end với KRaft nhúng (opt-in `RUN_KAFKA_IT=1`,
  `assume` skip khi thiếu); sbt + `project.scala`.
